# قواعد تنظيم الكود

## اتجاه الاعتماد

`app -> features -> components/lib/config -> types`

لا تستورد طبقة عامة من صفحة أو feature أعلى منها. الـbackend يتبع:

`controller -> service -> repository/Prisma`

## حجم ومسؤولية الملفات

- الصفحة تركّب الميزات ولا تنفذ منطق الأعمال.
- المكوّن يؤدي مسؤولية بصرية واحدة ويستقبل بياناته عبر props.
- الـservice ينفذ use-case واحدًا واضحًا ولا يعتمد على HTTP objects.
- DTOs والـvalidation خارج controllers عند نمو الوحدة.
- الثوابت والنصوص القابلة للتخصيص لا تتكرر داخل الملفات.

## التسمية

- أسماء عامة حسب الدور: `PlatformLogo`, `platformConfig`, `CourseCard`.
- تجنب اسم المدرس أو المادة في أسماء المكونات العامة.
- أسماء الأحداث أفعال، وأنواع البيانات أسماء، والقيم المنطقية تبدأ بـ`is/has/can`.

## الترحيل الآمن

الحفاظ على aliases مؤقتة مسموح لتجنب كسر imports، لكن كل alias يجب أن يحمل
`@deprecated` ويحذف بعد اكتمال نقل المستهلكين. لا تجمع إعادة تسمية ضخمة مع تغيير
سلوك الأعمال في نفس الخطوة.
